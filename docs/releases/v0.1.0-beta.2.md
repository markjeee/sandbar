# Sandbar v0.1.0-beta.2

This beta targets Linux amd64 with apt-packaged Caddy, systemd, Polkit, and sudo.
Ubuntu 24.04 is the tested platform. Install Caddy v2.11.7 or later separately.

## Breaking change: standard Caddy service

Sandbar now uses the standard `caddy.service` by default instead of a private user router.
Caddy starts at boot and owns ports 80 and 443. App backends must use other ports.
An explicit `--home` or `SANDBAR_HOME` still selects a private development router.
Sandbar remains a CLI and exits after each command.

Setup serves `https://sandbar.localhost` before any apps are configured and after the final app is removed.
App changes apply without restarting a running Caddy.

## Install and set up

```sh
curl -fsSL https://github.com/markjeee/sandbar/releases/download/v0.1.0-beta.2/install.sh | sh
export PATH="$HOME/.local/bin:$PATH"
sudo "$HOME/.local/bin/sandbar" setup --check --user "$USER"
sudo "$HOME/.local/bin/sandbar" setup --user "$USER" --replace-default-site
```

`--replace-default-site` backs up and replaces only Caddy's recognized stock welcome site. Custom sites remain protected.
Setup grants the named user access to **all Caddy routes and files Caddy can read**.
Grant this access only to users who may administer Caddy.
Log out and log back in after setup. A new terminal tab or pane does not refresh group membership.
Ordinary route commands then need no sudo.

Request certificate trust separately as your normal user:

```sh
sandbar trust
sandbar add app.sandbar.localhost 8000
sandbar status
```

Run the app on `127.0.0.1:8000`, then open `https://app.sandbar.localhost`.
The installer does not install Caddy, start services, edit shell profiles, or change trust.
Setup and migration do not change trust. Verify trust in your browser after `sandbar trust`.

## Upgrade from beta.1

Beta.1 routes require explicit migration. Installing beta.2 alone does not move routes or stop the old router.
Back up the old executable and record its configuration, state directory, and CA fingerprint before upgrading.
Use setup with both `--migrate-config` and `--migrate-state` to select the old instance.
Migration preserves route settings, root certificate bytes, and signing material. Existing trust stays valid when the root is identical.
Migration requires the old router to use ports 80 and 443 and causes a brief interruption during cutover.
Follow the [migration guide](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.2/docs/install.md#upgrade-from-the-private-router) before applying setup to an existing installation.

- [Installation, access, and removal](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.2/docs/install.md).

Other package layouts, service managers, operating systems, and architectures are not supported by this integration.
Routes accept connections only from this computer. App addresses must use loopback IP addresses or `localhost`.
HTTPS app addresses retain certificate verification.
`status` reports reachability. It does not prove application health, browser trust, DNS success, or operating-system listeners.

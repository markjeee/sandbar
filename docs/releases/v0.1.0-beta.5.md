# Sandbar v0.1.0-beta.5

This prerelease fixes setup recovery, failed-service startup, rollback metadata, and uninstall cleanup.
It retains beta.4's inspection, diagnostics, and installed cleanup, plus beta.3's Teleport and macOS support.
It targets Linux amd64 with apt Caddy, systemd, Polkit, and sudo, or macOS arm64 with native Homebrew Caddy.
Install Caddy v2.11.7 or a later v2 release separately. Ubuntu 24.04 is the Linux acceptance target.
macOS packages are unsigned and unnotarized. Intel Macs and Windows are not supported.

## Fixes

- Linux and macOS setup refuse pending route recovery before changes, including during `setup --check`.
  Resolve the reported transaction through [router recovery](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.5/docs/reference.md#router-state-and-recovery) before repeating setup.
  Setup preserves the journal and does not choose a recovery result.
- Explicit `sandbar start` can restart a verified failed owned service when its private admin endpoint is absent or refuses connections.
  Pending recovery resolves first. Sandbar stops the failed service and confirms shutdown before normal startup.
  Unresolved recovery, ambiguous admin access, or failed shutdown still blocks restart.
- Ordinary setup rollback restores original file contents, access mode, UID, and GID when Sandbar changed them.
  Matching bytes alone no longer skip metadata restoration. Conflicting external content or metadata edits remain protected.
- Installed uninstall includes the selected installation's empty owned SSH control directory even after its final Teleport destination was removed.
  Existing ownership, symlink, and content checks still apply. Unknown files or sockets remain conflicts.

## Install and upgrade

```sh
curl -fsSL https://github.com/markjeee/sandbar/releases/download/v0.1.0-beta.5/install.sh | sh
```

Packages need no compiler or Go runtime. The installer checks the matching archive's SHA-256 before atomic executable replacement.
Checksums share the HTTPS release source. They check transfer integrity, not an independent signature.
Linux defaults to `~/.local/bin/sandbar`. Add `~/.local/bin` to PATH.
macOS defaults to the regular executable `/usr/local/bin/sandbar`. Use `--bin-dir <directory>` for another destination.
The installer requests macOS administrator access only when final executable publication needs it.
It does not install Caddy, run setup, start services, edit shell profiles, or change trust.

Existing beta.3 and beta.4 installations need only executable replacement. No new schema migration or setup is required for these fixes.
Version 3 configuration, machine identity, routes, CA, Teleport registrations, services, and trust remain unchanged.
No new trust import is needed when CA identity is unchanged.
Setup, trust changes, connection changes, and uninstall remain separate explicit actions.

Fresh installations require separate setup. Run macOS setup as your normal user:

```sh
sandbar setup --check --http-port 80 --https-port 443
sandbar setup --http-port 80 --https-port 443
```

On Linux:

```sh
sudo "$HOME/.local/bin/sandbar" setup --check --user "$USER"
sudo "$HOME/.local/bin/sandbar" setup --user "$USER" --replace-default-site
```

`--replace-default-site` authorizes only Caddy's recognized stock welcome site. Custom sites remain protected.
Linux grants access to all Caddy routes and files Caddy can read. Grant access only to users who may administer Caddy.
Log out and back in after Linux group changes. A new terminal pane does not refresh membership.
Fresh CAs need a separate `sandbar trust` request as your normal user. Unchanged CA identity retains existing trust.

For beta.2 or older source, explicit setup upgrades configuration to version 3 and preserves supported routes, ports, and CA identity.
Keep the reported setup backup. Older binaries cannot read version 3 configuration.
Rollback requires matched source, generated configuration, setup files, and service state before using the older executable.
Keep original CA storage and trust. Private development upgrades require their matched source and generated Caddyfile backups.
Beta.1 users still need explicit private-router migration before service cutover.
Replacing the executable with beta.4 restores its previous behavior, including the four defects fixed here.
Follow [installation and recovery](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.5/docs/install.md) for earlier upgrades and rollback.

## Existing command and connection behavior

Use `sandbar config`, `sandbar status`, and `sandbar doctor` for [inspection and diagnostics](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.5/docs/reference.md#inspect-and-diagnose).
Uninstall still requires explicit confirmation, retains the CLI, and refuses shared sites.
Untrust failure preserves CA material and setup backups. Review [removal and recovery](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.5/docs/install.md#uninstall-installed-sandbar).
Both Teleport peers still need beta.3 or another Teleport-capable Sandbar, completed setup, and prepared remote Caddy and apps.
Apps must accept their machine-qualified URLs, including allowed hosts, CSRF origins, redirects, cookies, and login settings.
Browsers use the connecting machine's CA. Remote CA trust verifies only that destination's proxy transport.
Connect and reconnect remain explicit commands. See [Teleport](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.5/docs/teleport.md).

## Verification and limits

Native shared checks, CI, package verification, and public installation checks are separate release gates.
Public installation checks use temporary destinations without setup, trust changes, live uninstall, or installed executable replacement.
Ordinary Linux service CI does not establish privileged uninstall acceptance. The disposable Ubuntu uninstall acceptance remains deferred.
Actual macOS startup after logout/login remains deferred. Registration, start/stop, and inherited-socket checks do not establish that result.
Browser trust and manual import removal require separate checks. Package verification does not prove them.
Candidate versions without authored notes remain unpublished local packages.
See [development and acceptance](https://github.com/markjeee/sandbar/blob/v0.1.0-beta.5/docs/development.md) for check boundaries.
